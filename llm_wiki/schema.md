# LLM Wiki 운영 스키마

이 문서는 Dev Wiki의 LLM 분류기가 따라야 할 운영 규칙입니다. Karpathy의 LLM Wiki 패턴을 사내 업무 문서에 맞게 적용합니다.

이 문서는 **분류기의 프롬프트 컨텍스트로 그대로 주입**됩니다. 여기의 규칙을
고치면 분류 동작이 바뀝니다. 최종 목표와 배경은
`docs/decisions/DEC-002-llm-classification-and-change-history.md`를 보세요.

## 계층

1. Raw sources
   - 사용자가 업로드한 원본 글과 파일입니다.
   - 원본은 불변으로 보관합니다.
   - 경로: `llm_wiki/raw/YYYY/MM/{submission_id}/`

2. Draft wiki
   - LLM이 원본을 읽고 만든 초안입니다.
   - 승인 전에는 Docusaurus `docs/`에 반영하지 않습니다.
   - 경로: `llm_wiki/draft/{submission_id}.md`

3. Published wiki
   - 담당자 승인 후 Docusaurus `docs/` 아래 발행된 문서입니다.
   - 사용자는 `/wiki/` 사이트에서 읽습니다.

## 분류기가 돌려줄 값

분류기는 카테고리 하나만 고르지 않고 아래를 함께 돌려줍니다.

| 필드 | 설명 |
| --- | --- |
| `category` | 아래 다섯 개 중 하나. **목록 밖의 값은 허용하지 않습니다.** |
| `tags` | 주제 태그. 교차 탐색과 메뉴 하위 그룹의 근거 |
| `title` | 독자가 목록에서 읽을 제목 |
| `summary` | 한 줄 요약 |
| `reasoning` | 이 카테고리를 고른 근거. 문서의 「분류 결과」에 남김 |
| `confidence` | 0~1. 낮으면 자동 진행 대신 사람 확인을 요청 |
| `related` | 함께 읽을 기존 문서 후보 |
| `menu` | 메뉴에서의 상위 그룹과 순서 제안 |

발행 경로는 **서버가 만듭니다.** 모델이 준 경로를 그대로 쓰지 않습니다.

## 분류 카테고리

| 카테고리 | 발행 경로 | 설명 |
| --- | --- | --- |
| development | `docs/development/` | 아키텍처, API, 구현 지식, 데이터 모델 |
| operations | `docs/operations/` | 배포, 모니터링, 장애 대응, Runbook |
| standards | `docs/standards/` | 코딩 표준, 리뷰 규칙, 업무 규칙 |
| decisions | `docs/decisions/` | 기술/운영 의사결정 기록 |
| knowledge | `docs/knowledge/` | 위 범주에 속하지 않는 일반 업무 지식 |

## 메뉴 구성 규칙

메뉴는 분류 결과에서 생성합니다. 목표는 나열이 아니라 **독자가 차근차근
좁혀 들어가며 조사할 수 있는 구조**입니다.

- 각 카테고리는 개요 문서를 맨 위에 두고 세부 문서를 그 아래 배치합니다.
- 위에서부터 읽어 내려가면 맥락이 쌓이도록 순서를 정합니다.
- 문서가 많아지면 태그를 근거로 하위 그룹을 제안합니다.
- 선행 지식이 필요하면 먼저 읽을 문서를 가리킵니다.
- 사람이 고정한 순서와 라벨은 생성 결과보다 **우선합니다.**

## 처리 규칙

- 원문을 임의로 삭제하거나 덮어쓰지 않습니다.
- 초안에는 원본 출처, 작성자, 분류 이유, 관련 문서를 포함합니다.
- 기존 문서와 충돌 가능성이 있으면 `주의할 점` 섹션에 표시합니다.
- 보안상 민감한 토큰, 비밀번호, 개인정보는 발행 초안에 그대로 넣지 않습니다.
  **변경 이력에도 남기지 않습니다.**
- 승인 전에는 Docusaurus `docs/`에 반영하지 않습니다.
- 카테고리는 정해진 다섯 개 안에서만 받습니다. 그 밖의 값이 오면
  `knowledge`로 두고 `needs_reclassify` 상태로 사람 확인을 요청합니다.
- 제목과 요약은 프런트매터에 넣기 전에 반드시 따옴표 처리합니다.
  모델이 만든 문자열이 YAML을 깨면 위키 빌드 전체가 죽습니다.
- LLM 호출이 실패하면 키워드 규칙으로 물러나고 `needs_reclassify`로 둡니다.
  실패를 조용히 삼키지 않습니다.

## 기록 규칙

로그인한 사용자의 모든 기여는 **누가, 언제, 무엇을, 어떻게** 형태로 남습니다.

| 시점 | 기록할 것 |
| --- | --- |
| 제출 | 제출자, 시각, 원본 파일, 제목, 본문 |
| 분류 | 사용한 모델, 결과 카테고리, 근거, 확신도 |
| 수정 | 수정자, 시각, 바뀐 내용, 바뀌기 전 내용 |
| 승인·거절 | 심사자, 시각, 메모, 발행 경로 |
| 롤백 | 사유와 되돌린 지점 |

기록은 세 곳에 남깁니다. DB는 조회용, `llm_wiki/log.md`는 추적용 감사
로그, **문서 끝의 변경 이력은 독자용**입니다.

### 변경 이력

발행되는 모든 문서는 마지막에 `## 변경 이력` 섹션을 가집니다.

- 갱신할 때마다 **맨 위에 새 줄을 추가하고 기존 줄은 지우지 않습니다.**
- 각 버전은 그 시점의 본문 전문을 가리켜 **이전 기록을 참조할 수 있게**
  합니다. 개정본은 원본과 마찬가지로 불변 보관합니다.
- 변경 내용은 diff가 아니라 사람이 읽을 한 줄 요약으로 적습니다.
  요약은 LLM이 제안하고 기록자가 고칠 수 있습니다.
- 기록자는 로그인 계정의 **표시 이름**을 적고 이메일은 적지 않습니다.
- 재승인은 같은 경로를 덮어쓰고 버전을 올립니다. 접미사를 붙인 중복
  파일을 만들지 않습니다.

## 초안 형식

```md
---
title: 문서 제목
description: 한 줄 설명
tags: [category, source]
---

# 문서 제목

## 요약

## 주요 내용

## 분류 이유

## 관련 문서 후보

## 원본 출처

## 변경 이력

| 버전 | 일시 | 기록자 | 변경 내용 | 이전 기록 |
| --- | --- | --- | --- | --- |
| v1 | YYYY-MM-DD HH:MM | 표시 이름 | 최초 발행 (LLM 분류: category, 확신도 0.00) | — |
```
